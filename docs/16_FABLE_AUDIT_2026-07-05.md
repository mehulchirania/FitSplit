## Composite index audit (2026-07-05)

T3 enumerated every `.where(`/`.orderBy(`/`.collectionGroup(` chain in `src/lib/firebase/read-models/*.ts`,
`src/lib/firebase/actions/*.ts`, `src/lib/auth.ts`, and `functions/src/index.ts` — roughly 90 query sites
across ~20 files — and reconciled each reconstructed query shape against `firestore.indexes.json`. Single-field
`where`, `where`+`orderBy` on the same field, and single-field `.select()` scans need no composite index and were
excluded. `firestore.indexes.json` grew from 22 to 32 entries.

**Queries audited:** ~90 (all `read-models/`, `actions/`, `auth.ts`, and `functions/src/index.ts` query chains).

**Indexes added (10):**

| Collection | Scope | Fields | Query served |
|---|---|---|---|
| `programAssignments` | COLLECTION | `gymId ASC, memberId ASC, status ASC` | Root `programAssignments` cancel-existing-active lookup in `actions/programs.ts` (`assignProgramToMember`, `createAndAssignCustomProgram`) and `functions/src/index.ts` (`assignProgramToMember`) |
| `programAssignments` | COLLECTION | `memberId ASC, status ASC` | Gym-scoped `gyms/{gymId}/programAssignments` cancel-existing-active lookup in `actions/programs.ts`, `functions/src/index.ts` (`assignProgramToMember`, `bulkAssignProgram`), and `read-models/programs.ts` (`getProgramAssignmentForMemberUncached`, gym-scoped branch) |

**Flagged as possibly stale (left in place):** the pre-existing `profiles` COLLECTION index
(`defaultGymId ASC, role ASC, isActive ASC`, first entry in the file) targets the legacy root `profiles`
collection. A grep of every `collectionPaths.profiles` usage found only single-field `where` calls and direct
`.doc()` lookups — no live query currently uses this 3-field shape, and it appears to predate the `authProfiles`
rename/split. Left in place per the "when in doubt, keep it" rule rather than removed, since it costs little and
a caller not covered by this audit may still depend on it.
